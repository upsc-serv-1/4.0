# [FR-006] Safe Area Alignment Audit

## Labels
`MUS`, `bugfix`, `ux`, `safe-area`

## User Story
As an Android and iPhone user, I want my content to stay clear of notches, home indicators, and dynamic islands.

## Proposed Solution

### Overview
Review global `PageWrapper` uses and floating components (like the floating back buttons and FABs in Glance View) to ensure they respect safe area insets across devices, especially on Android where status bar overlay behavior differs from iOS.

### Implementation Flow
1. Inspect absolute-positioned FABs in `src/components/pilot-v2/PilotV2GlanceView.tsx`.
2. Wrap top-pinned elements or add dynamic margins using `useSafeAreaInsets()` from `react-native-safe-area-context`.
3. Ensure bottom content avoids overlapping the iOS home indicator bar or Android system gestures by adjusting `paddingBottom`.

### Technical Approach

```typescript
// Handling dynamic FAB offset with SafeAreaInsets
import { useSafeAreaInsets } from 'react-native-safe-area-context';

export function MyComponent() {
  const insets = useSafeAreaInsets();
  
  return (
    <View style={{ flex: 1 }}>
      <TouchableOpacity 
        style={[
          styles.floatingBtn, 
          { top: Math.max(16, insets.top) } // Dynamic Top margin
        ]}
      >
        <Icon name="arrow-back" />
      </TouchableOpacity>
    </View>
  );
}
```

### Key Considerations
- Never hardcode top offset to `20` or `44`. Android devices can have status bars ranging from 24px to 50px+ depending on pinhole cameras.
- The `PageWrapper` uses global `SafeAreaView`. If a child component already includes absolute safe elements, double-padding can occur if not explicitly managed via `edges` props.

## Acceptance Criteria

- [ ] Floating controls in Glance View never collide with top system text or notches.
- [ ] Modal dialogs are padded at the bottom to clear the home indicator.
- [ ] Consistent safe-margin alignment on both iOS and diverse Android device styles.
